# Step 1~3 피드백 — 의도 vs 구현 차이 정리

---

## 피드백 1 — ETF 선정 방식 (Step 2)

### 의도한 바
각 기초자산 슬롯별로, 각 시기별로 아래 순서에 따라 ETF를 선정한다.

1. **사전 필터링 (정성적 조건)**
   - 순수 지수 추종 상품 우선 (커버드콜·스트립·만기형 등 제외)
   - 비환헤지(unhedged) 우선

2. **가중평균 순위 산출 (정량적 조건)**
   - 총보수 순위: **50%**
   - 일평균 거래대금 순위: **30%**
   - AUM 순위: **20%**
   - 위 세 지표의 가중평균 순위가 가장 높은 ETF를 해당 슬롯의 대표 ETF로 확정(비중은 예시)

3. **적용 단위**
   - 연도별 × 슬롯별로 독립적으로 계산 (특정 연도에 AUM이 더 큰 ETF가 달라질 수 있으므로)

### 현재 구현된 방식
- AUM, 거래대금, 총보수 필터링 통과 후 **AUM 최대 ETF 단순 선정**
- 가중평균 순위 계산 없음
- 총보수가 낮거나 거래대금이 높은 ETF가 AUM이 작다는 이유로 탈락할 수 있음

### 수정 필요 사항
- 사전 필터링(순수 지수 추종 & 비환헤지) 조건을 1차 필터로 명시적으로 분리
- 통과한 ETF들을 대상으로 총보수(50%) + 거래대금(30%) + AUM(20%) 가중평균 순위 계산 로직 추가
- 이 계산을 **연도별 × 슬롯별**로 독립 실행하도록 구조 변경

## 피드백 2 — 롤링 윈도우 탐색 시 사용 데이터 (Step 3)

### 의도한 바
롤링 윈도우 탐색(적정 기간 산출) 단계에서는 **기초자산 자체의 장기 지수 데이터**를 사용한다.

- 사용 데이터: ECOS(한국은행), 코스피 지수, S&P 500 지수 등 기초자산의 전기간 증감률 시계열
- 이유: ETF는 상장 시점이 제각각이라 데이터가 짧고 슬롯마다 첫 등장 연도가 다름. 기초자산 지수를 쓰면 ETF 상장 이전 기간까지 포함하여 더 긴 기간에 걸친 분석이 가능하고, 윈도우 탐색의 신뢰도가 높아짐.

> **즉, 롤링 윈도우 탐색은 "어떤 ETF를 살지"가 아니라 "몇 년치 데이터를 봐야 하는가"를 결정하는 과정이므로, ETF 데이터가 아닌 기초자산 지수 데이터로 진행해야 함.**

### 현재 구현된 방식
- Step 2에서 선정한 ETF들의 수익률 시계열(`slot_returns.parquet`)을 그대로 롤링 윈도우 탐색에 사용
- 슬롯마다 첫 등장 연도가 달라 실제로 사용 가능한 구간이 제한됨

  | 슬롯 | 첫 데이터 연도 |
  |---|---|
  | 신흥국_인도, 해외채권_미국국채 | 2023~ |
  | 원자재_금 | 2021~ |
  | 미국주식_SP500·나스닥 | 2020~ |

  → 전체 13개 슬롯을 동시에 사용할 수 있는 구간이 2023년 이후밖에 없어 분석 기간이 매우 짧음

### 수정 필요 사항
- 롤링 윈도우 탐색용 데이터를 ETF 수익률이 아닌 **기초자산 지수 데이터**로 교체
  - 국내주식: 코스피, 코스닥 지수 (ECOS 또는 KRX)
  - 미국주식: S&P 500, 나스닥 지수
  - 채권: 국고채 금리 시계열 (ECOS)
  - 금: 금 현물 가격
  - 기타 자산군: 각 기초자산에 대응하는 대표 지수 또는 가격 시계열
- 가능한 한 2000년대 초반까지 소급하여 데이터 수집 → 윈도우 탐색 신뢰도 확보
- 실전 포트폴리오 구성(Step 4~)에서는 기존대로 ETF 수익률 데이터 사용

## 피드백 3 — 최적 윈도우 결정 기준 (Step 3)

### 의도한 바
단순히 OOS Sortino 평균이 가장 높은 윈도우를 선택하는 것이 아니라, 아래 **4가지 기준을 종합**하여 결정한다.

| 기준 | 설명 | 목표 방향 |
|---|---|---|
| OOS Sortino 평균 | 각 슬라이딩 구간에서 실현된 소르티노 비율의 평균 | 최대화 |
| 오차의 들쭉날쭉함 (σ) | 소르티노 비율의 표준편차. 낮을수록 예측이 일관적 | 최소화 |
| 평균 예측 오차 | 추정한 하방위험과 실제 하방위험의 차이 평균 | 최소화 |
| 이상치 구간 통제 | 금융위기·코로나 등 비정상 구간의 오차가 평균을 왜곡하지 않도록 보정 | 왜곡 방지 |

- 가중 점수 산식이 있다면, 각 기준의 가중치와 산정 근거를 명시할 것(이건 같이 찾아보거나, 적절하다 생각하는 비중으로 결정해도 됨)
- 이상치 구간은 단순 평균에 포함하기 전에 가중치를 낮추거나, 포함/제외 시나리오를 나란히 비교하여 결과의 왜곡 여부를 검증할 것

### 현재 구현된 방식
- OOS Sortino 평균이 가장 높은 **1년 윈도우를 최적으로 확정**
- 종합 점수(0.550) 산정 시 σ(일관성)도 포함되어 있으나, 평균 예측 오차 및 이상치 구간 보정은 별도로 검증되지 않음
- σ=2.05에 대해 "월별 Sortino의 특성상 정상 범위"로 해석하고 넘어감 → 윈도우 간 상대 비교만으로는 불충분

### 수정 필요 사항
- 평균 예측 오차(추정 하방위험 vs 실제 하방위험 차이)를 지표로 추가하고 윈도우별로 비교
- 이상치 구간(예: 2020 코로나, 2022 금리 급등기) 식별 후 해당 구간의 오차를 보정하여 평균 재산출
- 위 4가지 기준을 모두 반영한 종합 판단 후 최적 윈도우 확정

## 피드백 4 — MAR(최소 수용 가능 수익률) 임시값 (Step 3)

### 의도한 바
MAR은 **6개월 미만 정기예금 수신금리**를 리밸런싱 시점마다 갱신하여 사용한다.

- 출처: 한국은행 ECOS API
- 이유: 투자자가 지금 당장 아무 위험 없이 받을 수 있는 가장 접근하기 쉬운 금리를 기준으로, "이것도 못 이기면 투자 의미 없다"는 하방 기준선으로 설정

### 현재 구현된 방식
- 연 2.5%로 고정 (임시값)
- MAR이 고정되면 하방 공분산과 소르티노 비율이 실제와 달라지므로, 현재 결과는 실전 조건과 다름

### 수정 필요 사항
- Step 4에서 ECOS API를 통해 6개월 미만 정기예금 수신금리 시계열 수집
- 수집 후 **롤링 윈도우 탐색을 해당 금리로 MAR을 교체하여 재실행**
- 현재 확정된 "1년 윈도우"는 임시 MAR 기준 결과이므로, 실제 금리 적용 후 결과가 달라질 수 있음

## 피드백 5 — 리밸런싱 주기 (Step 3)

### 의도한 바
실전 리밸런싱 주기는 **분기(약 63거래일)**로 한다.

- 롤링 윈도우 탐색의 검증 구간도 실전 주기와 동일하게 **분기 단위**로 설정해야 윈도우 선택의 근거가 유효함

### 현재 구현된 방식
- 월별(21거래일) 리밸런싱 기준으로 검증

### 수정 필요 사항
- 검증 구간을 월별 → **분기(63거래일)** 단위로 변경하여 전체 롤링 윈도우 탐색 재실행
- 현재 확정된 1년 윈도우는 월별 기준 결과이므로, 분기 기준으로 다시 돌리면 최적 윈도우가 달라질 수 있음

---

## 수정 우선순위 요약

| 순서 | 항목 | 이유 |
|---|---|---|
| 1 | 리밸런싱 주기 변경 (월 → 분기) | 검증 기준 자체가 실전과 달라 윈도우 선택 근거 무효 |
| 2 | 롤링 윈도우 탐색 데이터 교체 (ETF → 기초자산 지수) | 데이터 기간이 너무 짧아 분석 신뢰도 부족 |
| 3 | MAR 교체 후 재실행 (임시 2.5% → 실제 정기예금 금리) | MAR이 달라지면 하방공분산·소르티노 전체가 달라짐 |
| 4 | ETF 선정 방식 변경 (AUM 최대 → 가중평균 순위) | 총보수·거래대금 반영 미흡 |
| 5 | 최적 윈도우 결정 기준 보완 (4가지 종합 기준 적용) | 단일 지표만으로 선택 시 왜곡 가능성 |

> 1~3번은 서로 연결되어 있으므로 순서대로 진행 후 롤링 윈도우 탐색을 한 번에 재실행하는 것을 권장합니다.
